# סביבת פיתוח ובדיקות מבודדת

סביבת הפיתוח משתמשת באדמין המקורי ב־`/admin/daycare`. קוד ה־Preview הניסיוני הוסר. התפריט הכחול ועיצוב מסכי הניהול נשמרו. ראו גם [דוח החזרה](admin-original-return.md) ו־[הפרדת קריאה מאתחול](daycare-overview-readonly-audit.md).

## הרצה מקומית

נדרשים Node.js, תלויות השרת והלקוח, mongod ו־Chrome. בדיקות הדפדפן דורשות גם Playwright. הנתיבים בפקודות הם מצייני מקום שיש להתאים למחשב; אין להשתמש בכתובת מסד או בסיסמת ייצור.

```sh
MONGOD_BINARY=/path/to/mongod npm --prefix server run dev
MONGOD_BINARY=/path/to/mongod npm --prefix server run dev -- --pilot
npm --prefix server test
npm --prefix client test
npm --prefix client run build
MONGOD_BINARY=/path/to/mongod npm --prefix server run test:db -- --all
MONGOD_BINARY=/path/to/mongod PLAYWRIGHT_MODULE=/path/to/playwright npm --prefix server run test:children:integration
```

הפעלת dev בונה את השרת ומפעילה Mongo ו־API חדשים. את Vite מפעילים בנפרד עם `npm run dev` בתיקיית `client`; הוא מגלה את ה־API ומאמת אותו אוטומטית. הרץ מדפיס כתובת אדמין ב־`http://localhost:5173/admin/daycare` ואת נתיב קובץ הסיסמה הזמנית בהרשאות 0600. אין שם משתמש; מזינים את הסיסמה הזמנית במסך הכניסה. אחרי הכניסה, שמפנה ללוח הבקרה, פותחים את כתובת `/admin/daycare` שהודפסה. Ctrl-C מסיים את תהליכי הסביבה שבבעלות הרץ ומסיר את תיקיית הנתונים הזמנית.

`--pilot` הוא opt-in מפורש להכנת פניות ותיקים בדויים, ורק אחרי אימות שהמסד חדש ומבודד. המסמכים, החתימות ומצבי התשלום הם fixtures בלבד; אין חיוב או שליחת הודעות. קוד המחולל נשמר במאגר, אך המסד, הקבצים שנוצרו והסיסמה אינם נשמרים בו.

## הגנות החיבור

- פיתוח ובדיקות אינם טוענים `.env`. חיבור הפיתוח דוחה `MONGO_URI` וכניסת production שאינה מפורשת.
- הרץ יוצר mongod חדש עם תיקיית נתונים פרטית, מסד בעל שם אקראי ופורטים אקראיים. הוא מאמת את PID של Mongo מול התהליך שבבעלותו לפני הכנסת סמן הזהות הראשון.
- manifest פרטי קושר את מצב ההרצה, PID, שם המסד ו־nonce. מתקבלים רק IPv4 loopback, פורט מפורש ושם מסד מהתבנית המנוהלת, ללא credentials או query overrides.
- השרת מאמת את סמן הזהות במסד אחרי החיבור. Vite ובדיקות האינטגרציה מאמתים גם הוכחת זהות של שרת HTTP.
- תהליכי הבדיקה מקבלים רשימת משתני סביבה מותרת בלבד, מפתחות זמניים ואחסון מסמכים זמני. תהליך השרת המנוהל טוען preload שחוסם תקשורת אל מחוץ ל־loopback.
- Vite משתמש ב־proxy המקומי המאומת וב־`/api`, ואינו טוען את `.env` של הלקוח בפרופיל זה. הפעלת Vite דרך `npm run dev` בלקוח ממתינה לסביבה המנוהלת של השרת; בלי API מאומת היא נעצרת. `vite preview` חסום; build רגיל נשאר אפשרי.
- רץ `test:db` יוצר אף הוא תהליכי Mongo ותיקיות חדשים, מסרב לפורטים תפוסים ומאמת את PID לפני הכנת המסדים.

אין להפעיל שרת ישן במקביל כדי לעקוף את הרץ המוגן. ההגנות מונעות טעויות תצורה; אינן תחליף להפרדת credentials והרשאות בתשתית ייצור.

## אתחול ותחזוקה

יצירת collections ואינדקסים אוטומטית של Mongoose כבויה. עליית השרת אינה יוצרת אינדקסים, מבצעת seed, מסנכרנת כותרות או מריצה reconciliation ו־backfill.

| פעולה | מנגנון מפורש |
|---|---|
| משימות, מסמכים תפעוליים והגדרות המעון | POST מוגן של אתחול המעון |
| אינדקסי שפרה ופועה, תיקי הצטרפות, הסכמים ותשלומים | פעולת תחזוקה נבחרת |
| טיוטת הסכם, שנת מסמכי הורים, תוכנית שנתית וקמפיין תרומה | פעולת תחזוקה נבחרת |
| סנכרון כותרות, התאמת שלבים והשלמת snapshots | פעולת תחזוקה נבחרת |

פעולות התחזוקה דורשות אימות אדמין, הגנת mutation ואישור מדויק לפעולה. השירותים מוגנים גם באמצעות הרשאה תחומה לזרימת הביצוע. קריאה אינה יוצרת נתוני בסיס. אתחול הסכם עם רשומות legacy מסרב למחיקה אוטומטית; אתחול מסמכי הורים אינו מתקן דגלי שיתוף ברשומות קיימות.

## בדיקות ומגבלות

בדיקות היחידות מכסות דחיית יעד מסד שגוי, סמן זהות שגוי, כניסת ייצור לא מפורשת ותחזוקה ללא הרשאה. בדיקות HTTP עם מודלים מדומים מכסות GET ללא כתיבה ואתחול מוגן.

האינטגרציה משתמשת ב־API, ב־Vite וב־Mongo זמניים אמיתיים. היא מכסה את הרישום המקורי במחשב ובמובייל, הערות, שיוך למשפחה, תהליך הורה ומסמכים, הסכם עם חתימה בדויה, ושכר לימוד עם מצבי תשלום מדומים. בדיקות הממשק המדומות מכסות גם כשלים וניסיונות חוזרים. אין בכך בדיקת ספקי תשלום/הודעות, callbacks חיצוניים, עומסים או הרשאות מסד ייצור.

## השלכות על פריסה עתידית

שמירה ב־Git אינה אישור לפריסה. בייצור נדרשים יחד `--production`, ‏`NODE_ENV=production`, ‏`MONGO_URI`, ‏`PRODUCTION_DATABASE_APPROVAL=ALLOW_PRODUCTION_CONNECTION` ו־`PRODUCTION_MONGO_DATABASE` המגדיר במפורש את המסד הקיים. אם הכתובת כוללת שם מסד, הוא חייב להתאים. בפריסה ותיקה ללא שם מסד בכתובת יש להגדיר במפורש את ברירת המחדל הקיימת `test`; manifest של פיתוח אסור בייצור.

לפני פריסה נדרשת בדיקה נפרדת של תצורת ההפעלה, האינדקסים הקיימים ונתוני הבסיס הנדרשים. מסד חסר תצורה עלול להחזיר שגיאה או רשימה ריקה במקום להיווצר אוטומטית. אין להריץ אתחול או תחזוקה ללא אישור מתאים. אתחול המעון אינו transaction או נעילה בין כמה מופעי שרת, ולכן דורש חלון תפעולי מבוקר עם כותב יחיד.
