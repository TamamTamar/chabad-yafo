# ילדים והרשמה - חיבור ראשון למערכת

תאריך: 18.10.2026. מימוש מקומי בלבד; ללא Commit, Push או Deploy.

## הפעלה

מתוך `client` מריצים `npm run dev`. נכנסים דרך `/admin/login` עם מנגנון האימות הקיים, ואז פותחים `/admin/daycare/children-preview` באותו שרת מקומי. לדוגמה בשרת Vite ברירת המחדל: `http://localhost:5173/admin/daycare/children-preview`.

לבדיקה המקומית הנוכחית הופעל שרת ב־`http://127.0.0.1:5191/admin/daycare/children-preview`, עם `VITE_API_URL=/api`, שמפנה לפי תצורת Vite הקיימת לשרת מקומי בפורט 4000. לא הופעל שרת האפליקציה ולא התחברנו למסד נתונים במסגרת העבודה. כדי להשתמש בנתונים מקומיים אמיתיים יש להפעיל בנפרד את סביבת הפיתוח המאושרת של השרת. יש לוודא את יעד `VITE_API_URL` לפני בדיקת פעולות כתיבה ידנית.

מסך הרישום הקיים נשאר ב־`/admin/daycare`, והוא עדיין יעד התפריט וברירת המחדל. אין קישור חדש בתפריט שמחליף אותו. המסך החדש מוגן ב־ProtectedRouteAdmin הקיים, כולל בדיקת session לפני mounting של המסך וקריאות הנתונים. אין אימות דמה או מתג client שמדלג על השומר. כל הקריאות משתמשות בשירותים הקיימים, שבשרת מוגנים ב־requireAdmin ובהגנות הפעולות הקיימות. אין שינוי בשרת, API, מודלים, הרשאות, תשלומים או תנאים עסקיים.

ההדמיה ב־`/__admin-preview__/` נשארת יישום נפרד בזיכרון עם נתוני דוגמה בלבד. נקודת הכניסה שלה אינה מייבאת את המסך החדש או שירותי הנתונים. קוד ההדמיה ונתוניה אינם כלולים בתוצר Build רגיל; רכיבי foundation והמסך המחובר כן כלולים. אין נתיב ציבורי חדש לנתונים אמיתיים.

## מה מחובר

- רשימת פניות ופרטי הילד/ה, ההורה, קשר, גיל, תאריך לידה, שעות ותאריך פנייה, דרך useDaycareRegistrations הקיים.
- חיפוש וסינון ב־URL (`q`, `status`), כולל שחזור ברענון ובחזרה מהתיק. גלילת הרשימה נשמרת ב־sessionStorage, ללא תוכן הרשומות.
- טיפול בפנייה ב־ModalDrawer הקיים מעל הממשק: שינוי סטטוס, עריכת הערה ושמירתה דרך השירות הקיים. הצלחה מוצגת רק לאחר תשובת שרת; כשל משאיר טיוטה לניסיון חוזר. בזמן בקשה השדות והמעברים מוגנים.
- פתיחת תיק רק בסטטוס הקיים „רוצה להירשם”, עם אותה ולידציית שנה, הערה פנימית, בחירת משפחה קיימת וסדר התאמה לפי טלפון. אין שכפול של מנגנון היצירה או החלטת הזכאות. ה־Preview מציג שגיאה וחוסם יצירה אם רשימת המשפחות לא נטענה, כדי שלא ליצור בטעות משפחה חדשה ללא יכולת לבחור קיימת.
- מעבר לתיק קיים וקיצורים למסמכים/אישורים ולשכר לימוד/הוראות קבע. יעד חזרה מוגבל במפורש לנתיב ה־Preview; יעד חיצוני אינו מתקבל. יעד החזרה נשמר גם כשהתיק מסיר את קישור ההורה מה־history state ובמעבר בין סעיפיו.
- הגנת טיוטה ב־X, Escape, backdrop, יציאה לרשימה וניווט הנתב; אישור השלכה מפורש ומיקוד בטוח בביטול. נוסף beforeunload בעת טיוטה או בקשה פעילה. סגירה משאירה את הרשימה mounted ומחזירה מיקוד לטריגר.

תיקון משותף קטן: ניקוי הערה שולח מחרוזת ריקה ל־API הקיים במקום undefined שהושמט מ־JSON. טיוטת ההערה מסתנכרנת אחרי שמירה עם תשובת השרת. התיקון חל גם על מסך הרישום הקיים.

## מה נשאר במסך המלא הקיים

תיק ההצטרפות, פרטי המשפחה המורחבים, מסמכים חתומים והורדות, אישור/החזרת מסמכים לתיקון, אישור מרוכז, הרשאות גישת הורה, שיבוץ ושלבים תפעוליים, שכר לימוד והוראות קבע. המסך החדש מפנה ליכולות אלה ואינו מממש מחדש את הבדיקות או התשלומים שלהן. תפעול המעון, כספים ומידע להורים לא הועברו לעיצוב החדש בשלב זה.

## בדיקות

- client: `npm run build` כולל TypeScript ו־Vite, `npm run lint`, `npm test` - עברו ללא אזהרות ESLint. בדיקת הניווט הקיימת הורחבה להכרה ב־Preview תחת המעון.
- server: `npm test` כולל TypeScript - 148 בדיקות, 143 עברו, 5 בדיקות DB דולגו. לא הופעל `test:db`. נדרש להריץ מחוץ לסנדבוקס בגלל שימוש במאזיני HTTP מקומיים של הבדיקות; לא שונו נתוני ייצור.
- בדיקות Chrome headless ברוחבי 1440 ו־390, עם 60 פניות סינתטיות. כל `/api` נענה בתוך Playwright, וכל בקשה למקור חיצוני נחסמה. שום פעולת כתיבה בבדיקה לא הגיעה לשרת או למסד.
- בדפדפן: 401/403 מפנים לכניסה ללא קריאות נתוני רישום; חיפוש/סינון/רענון, שחזור גלילה לא־אפס ברשימה ארוכה, מצב ריק ושגיאת טעינה, Drawer ורוחבו, מקלדת ומיקוד, Escape/X/backdrop והשלכה/ביטול, שינוי סטטוס, כשל שמירת הערה וניסיון חוזר, ניקוי הערה, ולידציית יצירה, כשל יצירה וניסיון חוזר, חזרה לרשימה לאחר יצירה, וחסימת יצירה בכשל טעינת משפחות.
- נבדק מעבר מ־Preview לתיק מלא מדומה, אישור המסמכים במנגנון הקיים עם כשל וניסיון חוזר, ועדכון ארבעת חלקי האישור לאחר תשובות מדומות בלבד. נבדקה חזרה מהתיק לרשימה המסוננת. אין בכך אימות אינטגרציה מול שרת אמיתי.
- נבדקו צילומי מחשב ומובייל. נשמרו צילומים ב־`/tmp/registration-preview-{1440,390}.png` ו־`/tmp/registration-drawer-{1440,390}.png`. טופל מרווח לכפתור הניווט של המעטפת במובייל.
- סריקת dist: לא נמצאו שמות ילדי ההדגמה או נקודת הכניסה של ההדמיה. `git diff --check` עבר.

הרצת בדיקת הדפדפן: מפעילים שרת Vite ב־5191 עם `VITE_API_URL=/api`, ואז `node client/scripts/test-registration-preview.cjs` משורש המאגר. נדרשים Playwright ו־Chrome; ניתן להגדיר `PLAYWRIGHT_MODULE` לנתיב מודול Playwright מותקן. אין צורך בשרת backend. הסקריפט אינו חלק מ־npm test משום שהוא דורש שרת פיתוח ודפדפן מקומיים.

לא נבדקו: אימות עם חשבון אמיתי או שמירות מול שרת/מסד אמיתי, ספק התשלום, הורדות מסמכים אמיתיים, מכשיר נייד פיזי, קורא מסך, סגירת חלון פיזית עם beforeunload ושינוי הגדרת reduced-motion במערכת. הבדיקות אינן אישור לשינוי סביבת ייצור.

## השלמת מעטפת ה־Preview - 18.10.2026

`ProtectedRouteAdmin` קיבל אפשרות תצוגה `layout="standalone"`. בדיקת `/auth/me`, מצב הטעינה וההפניה לכניסה נשארו לפני הצגת התוכן ללא שינוי. רק נתיב `children-preview` משתמש באפשרות; ברירת המחדל נשארת `legacy` עם AdminShell. ה־Preview מרכיב כעת AdminWorkspaceShell מתוך foundation במקום AdminFoundation מקונן בתוך AdminShell.

המעטפת כוללת חיפוש עליון יחיד המחובר ל־q, ניווט ראשי אופקי לאזורי המערכת האמיתיים, כותרת המעון והאיור מההדמיה, ניווט תחומי המעון, אזור עבודה וסיכום טיפול מהנתונים הקיימים. במובייל משתמשים בתפריט תחומי הפעילות של המעטפת החדשה. פעולת היציאה משתמשת ב־logoutAdmin הקיים. אין sidebar ישן, כותרת h1 נוספת או main כפול. AdminShell הישן לא שונה בשלב זה.

השוואה חזותית ישירה להדמיה ב־5178: אותם foundation shell, צבעים, טיפוגרפיה, כותרת מעון, איור קווי, שורת ניווט, rail משני ו־Drawer מעל הממשק. במובייל התוכן קודם לסיכום, וה־Drawer ברוחב המסך. בהדמיה יש חמישה יעדי ניווט מדומים; במסך המחובר יש שלוש קבוצות המפנות למסכים הקיימים. נתוני סיכום/סטטוסים נלקחים מהפניות הקיימות, והחיפוש מרוכז בשדה העליון כדי להימנע מחיפוש כפול.

המסך נפתח גם בדפדפן האפליקציה עם session קיים: אומתו נתונים לאחר גישה ישירה, הופעת הניווט האופקי ופתיחת וסגירת Drawer, ללא כתיבה לנתונים. התחברות חדשה באמצעות סיסמה לא בוצעה. בדיקות Chrome עם API מדומה עברו מחדש ברוחבי 1440 ו־390, כולל רענון, גישה ישירה, חזרה לרשימה, כל בדיקות הפעולות הקודמות, תפריט המובייל החדש, h1 ו־main יחידים והיעדר תפריט האדמין הישן. נבדקו שוב חסימות 401/403. TypeScript/Build, ESLint והרגרסיות הקיימות עברו.
