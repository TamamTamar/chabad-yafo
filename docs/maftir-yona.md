# מכירת זכות מפטיר יונה

## מיפוי התשתית והשתלבות

- `client`: React 19, TypeScript, Vite, React Router (`src/app/router.tsx`), SCSS Modules. מעטפת `Root` מספקת את סגנונות הבסיס, הכותרת והתחתית; האדמין משתמש באותה מעטפת ללא כותרת ציבורית.
- `server`: Express, Mongoose 9, חיבור MongoDB הקיים ב־`config/connectDB.ts` באמצעות `MONGO_URI`. הראוטים החדשים נרשמים ב־`index.ts`; לא נוסף שרת נוסף.
- המודלים הקיימים כוללים משפחות, תשלומים, רישומים, פרויקטים, מסמכי מעון וקמפיין תרומות למעון. המכירה משתמשת באוספים משלה בלבד: `maftiryonaauctions`, `maftiryonabids`, `maftiryonaratelimits`.
- ההזדהות הקיימת: `adminAuth.ts`, JWT ב־cookie או bearer, `ProtectedRouteAdmin`, `http.ts` עם credentials; הפעולות החדשות משתמשות גם ב־`requireSecureAdminMutation` לבדיקת origin ו־JSON. לא נוצר מנגנון הזדהות נוסף.
- קיימים שירותי Twilio WhatsApp ו־SMTP (`whatsapp.ts`, `mail.ts`) להודעות רישום. המכירה אינה שולחת הודעות אוטומטיות ולא מפעילה אותם.
- נבדקו `DonationCampaignPage`, כל רכיבי הקמפיין והמודאל, טיפוסי הקונפיגורציה, סגנונות הכרטיסים והטפסים, מעקב האירועים, `buildNedarimPayload`, `useNedarimIframe`, מסגרת התשלום ו־`paymentRoutes`.
- דף הקמפיין מקבל קונפיגורציה מהעמודים העוטפים אותו; הוא אינו API ליצירת מכירה או קישור אישי. הסליקה שבו נעשית ב־iframe של נדרים פלוס, עם `FinishTransaction2` ו־callback קיים לשמירת תשלום. מסמך קמפיין המעון אינו משמש למכירה.
- העמוד החדש משתמש ב־`_variables.scss` וב־`_base.scss` שכבר נטען באתר, בכרטיסים לבנים, כחול המותג, זהב, טפסים וכפתורים תואמים. חלונות אישור משתמשים ב־`ConfirmDialog` הקיים. לא שונו רכיבי קמפיין התרומות, ולא נוספו תמונות או צבעי מותג משוכפלים.

## הפעלה וניהול

העמוד הציבורי: `/maftir-yona`. מסך הניהול: `/admin/maftir-yona`, עם כפתור בדשבורד הקיים.

לא נוצרים נתוני מכירה בזמן build או בהפעלת השרת. במסך האדמין לוחצים **יצירת מכירה נפרדת**, בודקים את ההגדרות ואז **פתיחת המכירה**. לפני יצירה/פתיחה העמוד הציבורי מציג שהמכירה טרם נפתחה. ברירת המחדל היא 1,800 ₪, תוספת 180 ₪ וסיום ב־20.9.2026 בשעה 14:18 ב־Asia/Jerusalem, שנשמר כ־`2026-09-20T11:18:00.000Z`. זהו המועד שנמסר בדרישה; לא מתבצע חישוב חדש של כניסת החג.

ניתן לשנות מחיר פתיחה, תוספת ומועד סיום, לעצור זמנית, להמשיך ולהאריך בדקות. סגירה סופית דורשת אישור ולא מאפשרת פתיחה מחדש. פסילה דורשת אישור, נשמרת עם זמן ומזהה מנהל, ומחשבת מחדש מוביל/זוכה, גם לאחר סגירה. הצעות קיימות אינן נמחקות. אם אין הצעות פעילות אין זוכה. שינוי הגדרות או הצעה בזמן עריכת אדמין מחייב רענון השדות לפני שמירה.

המינימום הראשון הוא מחיר הפתיחה; בהמשך המקסימום בין מחיר הפתיחה לבין ההצעה המובילה בתוספת המינימלית. סכומים שלמים בלבד, עם גבול קלט של מיליארד שקלים. קיצורי 180/360/770 מוסיפים לסכום המוביל (או למחיר הפתיחה לפני הצעה ראשונה), ובכל מקרה מכבדים את המינימום שהאדמין הגדיר.

## אטומיות, זמן ופרטיות

כל פעולת שינוי כותבת תחילה את מסמך המכירה בתוך טרנזקציית MongoDB. הצעה, עדכון המוביל, הארכת הזמן ופסילת הצעה נשמרים יחד. התנגשות כתיבה מפעילה retry של הטרנזקציה, ובו נבדקים מחדש הגרסה, המינימום וזמן השרת. גרסה ישנה מקבלת HTTP 409 ומחייבת אישור נוסף, גם אם הסכום הישן עדיין גבוה מספיק. אין מנעול בזיכרון של תהליך יחיד.

כל בקשה כוללת UUID למניעת כפילות, עם אינדקס ייחודי למכירה ולמזהה. ניסיון חוזר עם אותם פרטים מחזיר את אותה ההצעה; מזהה חוזר עם פרטים אחרים נדחה. בדפדפן ננעלת שליחה כפולה, ובהיעדר תשובה נשמרים פרטי הבקשה לניסיון חוזר באותו מזהה.

הצעה שהתקבלה בחלון האחרון של 120 שניות מעדכנת את הסיום לזמן קבלתה בשרת ועוד 120 שניות. אפשר לחזור על ההארכה. מרגע הסיום ההגשה נחסמת בשרת גם ללא ביקור בעמוד. בקשת הקריאה הבאה שומרת אטומית סטטוס סופי ומזהה זוכה; לאחר restart המצב מחושב ונשמר באותו אופן, ללא תלות בטיימר שרת שאבד.

Polling כל 4 שניות, ללא בקשות קריאה חופפות מתוך אותו hook. כל תשובה כוללת `serverTime` ו־`endsAt`, ומשך הזמן ביניהם מתקדם עם `performance.now()` שאינו תלוי בשעון המכשיר. תשובות ישנות אינן דורסות גרסה חדשה. אחרי 15 שניות ללא סנכרון הטופס מושבת; באפס שניות הוא מושבת וממתין לאישור הסיום מהשרת כדי לא להכריז על זוכה לפני קבלת הארכה אפשרית. בהגעה לסטטוס סופי התצוגה נשארת על אפס.

ה־API הציבורי בונה DTO מפורש עם סכום, שם פרטי ואות אחת משם המשפחה, זמן ומזהה הצעה בלבד. הוא מציג חמש הצעות פעילות אחרונות ואינו כולל טלפונים, שמות משפחה מלאים, פרטי פסילה או קישור תשלום. תשובות אינן נשמרות ב־cache. שם מלא וטלפון נגישים רק בנתיבי האדמין.

מגבלת הגשה משותפת לכל תהליכי השרת: 20 ניסיונות לדקה ל־IP ו־6 לטלפון מנורמל, באמצעות מוני MongoDB אטומיים עם TTL. מונים נשמרים כ־HMAC עם `JWT_SECRET` הקיים; ההצעה שומרת HMAC של IP, ללא כתובת גולמית. משתמשים בהגדרת `trust proxy` הקיימת. רישום שגיאות חדש כולל רק שם פעולה וקוד טכני, ללא פרטי מציעים.

## דרישות סביבה וסליקה

אין משתני סביבה חדשים להפעלה. נדרשים `MONGO_URI`, `JWT_SECRET`, `ADMIN_PASSWORD` ו־`CLIENT_ORIGIN` הקיימים; הלקוח משתמש ב־`VITE_API_URL` הקיים.

**MongoDB חייב לתמוך בטרנזקציות: replica set או Atlas/sharded cluster.** מסד standalone אינו מתאים למימוש האטומי הזה. הבדיקות נעשו ב־replica set מקומי; לא בוצעה בדיקה או שינוי של מסד production. חיבור שלא תומך בטרנזקציות נכשל עם הודעת זמינות ואינו שומר הצעה חלקית. אם אינדקסים אוטומטיים כבויים בסביבת האירוח, יש ליצור את האינדקסים המוגדרים במודלים לפני הפתיחה.

אין חיבור ל־Cardcom. בנדרים פלוס הקיים לא נמצאה פעולה מתועדת ליצירת URL אישי שמשתף סכום ופרטי זוכה. לא הומצאו פרמטרים או כתובות, ולא הועברו פרטים לכתובת כללית. באדמין לאחר סיום יש **העתקת פרטי הזוכה והסכום לתשלום**, שמרעננת את פרטי הזוכה לפני ההעתקה. כדי לשלוח קישור אוטומטי נדרש מנגנון מתועד של נדרים פלוס ליצירת קישור אישי, או תשתית נוספת של קישור מאובטח לטופס התשלום. ההעתקה אינה שולחת הודעה, יוצרת חיוב או מאשרת שהזוכה שילם.

## בדיקות

בדיקות כללים: `server/src/tests/maftirYonaRules.test.ts`.
בדיקת אינטגרציה: `server/src/tests/maftirYonaRoutes.test.ts`.

הבדיקה האינטגרטיבית מותרת רק מול URI מקומי בתבנית מוגבלת, ומוחקת **רק את מסד הבדיקה** בסיומה:

```sh
MAFTIR_TEST_MONGO_URI='mongodb://127.0.0.1:27039/maftir_qa_integration?replicaSet=maftirqa' npm test --prefix server
npm test --prefix client
npm run build --prefix client
npm run build --prefix server
```

ללא `MAFTIR_TEST_MONGO_URI`, בדיקת MongoDB מסומנת skip; בדיקות הכללים עדיין רצות. אין שימוש ב־`MONGO_URI` של האתר לצורך הבדיקה. משתנה זה מיועד לבדיקות בלבד.

כיסוי אוטומטי: הצעה ראשונה, מתחת למינימום, סכומים לא שלמים, שתי בקשות מקבילות, שליחה כפולה, הארכה חוזרת, סוף מדויק, עצירה/טרם פתיחה, פסילת מוביל, פרטיות, הרשאות ו־origin, מגבלת קצב לפי שני המזהים, התמדה בקריאה חדשה, זוכה סופי, המרת שעון קיץ/חורף בישראל ודחיית שעה כפולה או חסרה במעבר שעון.

בדיקת דפדפן מקומית עם נתוני דמה בלבד: רוחבי 1440, 390 ו־320, חלון אישור והצעה ראשונה, polling, רענון, טופס עם הצעה ישנה, פסילת מוביל וסגירה באדמין. הדפדפן הוגדר לאזור זמן אמריקאי; התאריכים נשארו לפי ישראל. בקשות לאתרים חיצוניים נחסמו בבדיקה. לא בוצעו סליקה או משלוח הודעות.

## עדכון העיצוב — 16.9.2026

נוספה פתיחה בכחול עמוק וזהב, הסבר קצר על משמעות העלייה וחיבור מקומי ליפו. ההסבר מבוסס על [הפטרת יונה ולקחיה — צעירי חב״ד](https://www.chabad.org.il/Magazines/Article.asp?ArticleID=10888&CategoryID=1892); אזכור יפו מבוסס על יונה א, ג ועל [הסבר הקריאה באתר הכותל](https://thekotel.org/he/129286/). אין הבטחה לתוצאה רוחנית או כלכלית בעקבות הצעה.

בחירת הסכום מופיעה לפני הפרטים האישיים. נוספו הצעות בחירה 3,600 / 5,400 / 7,700 ₪; עם עליית המינימום הן מתעדכנות לסכום שאינו נמוך מהמינימום ועוד 1,800 / 3,600 / 5,900 ₪ בהתאמה. אין בחירה אוטומטית ואין סימון פיקטיבי של פופולריות. נשמרו סכום חופשי וקיצורי 180 / 360 / 770 ₪. כפתור ההגשה וחלון האישור מציגים את הסכום הנבחר. במובייל כפתור מעבר לטופס מוסתר כאשר הטופס מופיע במסך.

העיטור נבנה ב־CSS ובאייקון קיים; לא נוספו תמונות. העדכון אינו משנה את שרת המכירה או את התנהגות דף התרומות. בדיקת הדפדפן לעדכון העיצוב נעשתה עם API מדומה בלבד, ברוחבי 1440 / 390 / 320, כולל בחירת סכומים, אישור, הגשה אחת וסטטוס סיום.
